# V0.4 Ruler & Measurement Implementation Plan

> **For agentic workers:** Implement this plan task-by-task. Each task is TDD-driven (test first, then implementation). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add element size, viewport distances, parent distances, dual-element measurement, and persist them into records. Output measurements in JSON (`version: "0.4"`) and AI Prompt. Keep V0.3 record metadata, edit/delete, filtering, and grouped Prompt intact.

**Architecture:** Keep V0.3 MV3 architecture. New code lives in:
- `extension/src/content/measurement.ts` — pure functions to compute size / viewport / parent / pair distances
- `extension/src/overlay/measurement-layer.ts` — Overlay rendering for size label and pair distance lines
- `extension/src/panel/components/MeasurementPanel.tsx` — Panel UI for size / viewport / parent groups + measurement mode buttons
- Existing files updated: `types.ts`, `session-store.ts`, `prompt-template.ts`, `CommentEditor.tsx`, `App.tsx`, `panel-root.tsx`, `content/index.ts`, `overlay-root.ts`

**Tech Stack:** Chrome Extension MV3, TypeScript, Vite, React, Vitest, Shadow DOM.

- [ ] **Step 3: Handle measurement mode click logic**:

  - If `awaiting-b`: store as `pairSecondElement`, advance to `complete`, recompute pair measurement.
  - If `complete` or `off`: existing V0.3 behavior.
  - If editing record (V0.3): block element click (already implemented).

  - `toggleAttachMeasurements(next)` → set `runtime.attachMeasurements = next`.

- [ ] **Step 5: Modify `saveRecord` / `updateRecord`**:
