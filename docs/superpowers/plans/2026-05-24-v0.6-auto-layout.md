# V0.6 Auto Layout Implementation Plan

**Goal:** Add lightweight layout context capture and layout intent records. Keep V0.5.5 UI, V0.5 shared ranges, V0.4 measurements, and V0.2 style preview intact.

## Completed Tasks

1. **Types and JSON version**
   - Added `LayoutContext`, `LayoutIntent`, and optional `EditRecord.layoutContext/layoutIntent`.
   - Bumped `DATA_FORMAT_VERSION` to `0.6`.
   - Added `0.6` to supported import versions.

2. **Session store compatibility**
   - `createInitialSession()` now creates V0.6 sessions.
   - `addEditRecord()` and `updateEditRecord()` can preserve layout fields.
   - Import normalization preserves valid V0.6 layout fields and defaults older versions to `null`.

3. **Layout inspector**
   - Added `content/layout-inspector.ts`.
   - Reads direct parent selector, display, flex/grid alignment fields, gap, child index, and sibling count.
   - Includes unit tests for flex and non-flex parents.

4. **Panel UI**
   - Added `LayoutPanel`.
   - Shows layout facts, direction/alignment controls, target gap, note, and save action.
   - Integrated after Similar Elements and before Measurement / Style Editor.

5. **Content runtime integration**
   - Runtime now keeps `currentLayoutContext`.
   - Selection, scroll, and resize update layout context.
   - `saveLayoutIntent()` creates `category: "layout"` records with structured layout fields.

6. **Prompt output**
   - `buildAiPrompt()` now emits a “布局辅助” subsection when layout fields exist.

7. **Tests and quality gate**
   - Added layout import/export and Prompt tests.
   - `npm run verify` passes with 93 unit tests, TypeScript, and Vite build.

8. **Chrome content smoke**
   - Verified content script enablement on `extension/test-pages/basic.html`.
   - Selected `#save-button`, confirmed LayoutPanel appears and reads parent `display: flex` with `12px` row/column gap.
   - Saved a layout intent with horizontal direction, centered alignment, `16px` gap, and note; runtime record persisted `layoutContext` and `layoutIntent`.
   - This smoke uses a page-level content script harness because the current remote debugging environment cannot call `Extensions.loadUnpacked` over the port API and `--load-extension` does not expose `chrome.scripting` in the inspected worker context. Manual extension icon validation is still required.

## Manual Acceptance Steps

1. Load `extension/dist` in Chrome via `Load unpacked`.
2. Open `extension/test-pages/basic.html`.
3. Select an element inside a flex-like container.
4. Confirm “布局辅助” shows parent selector, display, direction, alignment, gap, and child order.
5. Save a layout intent with direction, alignment, gap, and note.
6. Export JSON and confirm `version: "0.6"` plus `layoutContext` / `layoutIntent`.
7. Copy Prompt and confirm it contains “布局辅助”.
8. Re-import the JSON and confirm the layout record remains visible.

## Known Boundaries

1. Only direct parent layout is captured.
2. No automatic layout mutation is applied to the host page.
3. Grid details beyond display/gap/alignment are not parsed in V0.6.
