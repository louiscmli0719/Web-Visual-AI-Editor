# Web Visual AI Editor V0.3 Comment Enhancement Spec

## 1. Problem / Opportunity

V0.1 + V0.2 已经把"选元素 → 写评论 / 调样式 → 导出 JSON / Prompt"的闭环跑通了，但记录本身还很扁：

1. 一条评论只有自由文本，缺少"这是视觉问题还是交互问题"的元信息。
2. 用户没法说"这个 hover / loading / empty 状态要怎么处理"，只能塞在评论文本里。
3. 用户没法说"这是必改"还是"备注"，AI / 开发拿到 Prompt 后无法排优先级。
4. 没法在不选元素的情况下记录页面级反馈（比如"整体节奏太挤"）。
5. 写错了的评论没法编辑，只能新加一条。
6. Prompt 全部记录混在一起，AI 拿到后难以按主题处理。

V0.3 的机会是把"评论"从一条文本升级为带类型 / 优先级 / 状态 / 作用域 / 交互态的结构化反馈单元，让 AI / 开发能更准确地理解和排程。

## 2. Goal and Success Metrics

目标：在 V0.2 的元素选择 + 样式预览基础上，为每条记录增加分类、优先级、状态、交互态、作用域；支持页面级评论、支持编辑/删除现有记录；Prompt 按类型分组输出。

成功标准：

1. 用户保存评论时能选择类型、优先级、交互态（可选）。
2. 用户能在不选元素时直接写页面级评论。
3. 用户能修改已有记录的评论文本、类型、优先级、状态、交互态。
4. 用户能删除已有记录（带二次确认）。
5. 记录列表能筛选/排序按类型或状态。
6. 导出 JSON 包含新字段，并且能向后兼容导入 V0.1 / V0.2 JSON。
7. AI Prompt 中记录按类型分组，并标注优先级与交互态。
8. V0.2 的样式预览闭环不被破坏。

## 3. Target Users and Main Scenarios

| 用户 | 场景 | V0.3 要解决的问题 |
|---|---|---|
| AI 编程用户 | 把改稿单丢给 Codex / Cursor | Prompt 中分类清晰、有优先级，AI 能按主题执行 |
| 产品经理 | 验收页面、列出阻塞问题 | 一眼看出哪些是必改、哪些是建议；能记录"按钮 hover 应该变深一档"这种状态级反馈 |
| UI/UX 设计师 | 体验 Review | 能区分视觉 / 交互 / 文案问题，能为同一元素记录多个状态 |
| 前端开发者 | 接收混合反馈 | 知道哪些是状态级修改，避免遗漏 hover / empty / error |

## 4. Scope

### 4.1 记录元信息

每条 `EditRecord` 新增：

| 字段 | 类型 | 取值 | 默认值 | 说明 |
|---|---|---|---|---|
| `category` | enum | `visual` / `copy` / `interaction` / `layout` / `data` / `state` | `visual` | 评论类型 |
| `priority` | enum | `low` / `medium` / `high` | `medium` | 优先级 |
| `status` | enum | `open` / `resolved` / `deferred` | `open` | 状态（V0.1 已有 `open`/`resolved`，新增 `deferred`） |
| `interactionState` | enum \| null | `default` / `hover` / `focus` / `active` / `disabled` / `loading` / `empty` / `error` | `null` | 交互态，可选；与 `category: interaction` 配合最自然 |
| `scope` | enum | `element` / `page` | `element` | 作用域，决定记录是否依赖 `element.selector` |
| `element` | ElementSnapshot \| null | — | — | `scope: page` 时为 `null` |
| `updatedAt` | ISO string | — | — | 编辑或状态改变时刷新 |

类型中文映射（UI 展示）：

- `visual` 视觉
- `copy` 文案
- `interaction` 交互
- `layout` 布局
- `data` 数据
- `state` 状态

优先级中文映射：

- `low` 低
- `medium` 中
- `high` 高

状态中文映射：

- `open` 待处理
- `resolved` 已处理
- `deferred` 暂缓

交互态中文映射：

- `default` 默认
- `hover` 悬停
- `focus` 聚焦
- `active` 按下
- `disabled` 禁用
- `loading` 加载
- `empty` 空状态
- `error` 错误

### 4.2 Comment Editor 升级

输入：选中元素或页面级评论入口、用户输入。

处理：

1. 在评论输入框旁新增 `category` 下拉、`priority` 下拉。
2. 当 `category = interaction` 或 `category = state` 时，展开 `interactionState` 下拉；其他类型不强制选择。
3. 保存按钮触发保存逻辑，写入完整元信息。
4. `scope: page` 时，禁用元素相关展示，按钮显示"保存页面评论"。

输出：评论记录写入 session，带完整元信息。

### 4.3 页面级评论入口

输入：用户点击 Panel 顶部"页面评论"区域。

处理：

1. Panel 在元素信息上方常驻"页面评论"折叠区。
2. 默认折叠，展开后可写入 / 浏览 / 编辑 / 删除页面级记录。
3. 页面级评论同样支持 `category` / `priority` / `status`，但 `interactionState` 默认禁用。
4. 不写入 `element`，`selector` 字段空。

输出：用户能直接发起页面级反馈，不需要先选元素。

### 4.4 记录列表升级

输入：当前所有 `EditRecord`。

处理：

1. 列表项展示：selector 摘要（或"页面评论"）、类型徽标、优先级徽标、状态徽标、交互态（如存在）、评论摘要、样式修改摘要（保留 V0.2 行为）。
2. 新增筛选条：按状态（全部 / 待处理 / 已处理 / 暂缓）、按类型快捷过滤（全部、视觉、文案、交互、布局、数据、状态）。
3. 排序保持"按创建时间升序"，V0.3 不引入多排序键。
4. 每条记录新增"编辑"和"删除"按钮。
5. 状态切换通过点击状态徽标下拉切换。

输出：用户能在面板里管理记录，包括编辑、删除、状态切换。

### 4.5 记录编辑

输入：用户点击某条记录的"编辑"。

处理：

1. 进入编辑模式：把当前评论文本、类型、优先级、交互态、状态注入 CommentEditor。
2. 编辑过程中保留原 `id`、`createdAt`、`element`、`styleChanges`，刷新 `updatedAt`。
3. 完成编辑后回到默认 CommentEditor。
4. 编辑模式中禁止再次点击元素切换选中（避免误覆盖编辑目标）；提供"取消编辑"按钮。

输出：用户能修正过往评论而无需删除重建。

### 4.6 记录删除

输入：用户点击"删除"按钮。

处理：

1. 弹出二次确认（Panel 内浮层或 inline 确认，避免使用 `window.confirm` 影响宿主页面）。
2. 确认后从 session 移除记录，清理 `unmatchedRecordIds`。
3. 不做撤销（V0.3 不引入历史栈）。

输出：记录被永久移除，列表刷新。

### 4.7 状态切换

输入：用户点击状态徽标。

处理：

1. 弹出 inline 下拉，可切换 `open` / `resolved` / `deferred`。
2. 状态变更同步刷新 `updatedAt`。
3. 筛选条件下，状态切换可能让该记录从当前筛选视图中消失，需要有 toast 或状态消息提示"已切换为已处理，可在筛选中查看"。

输出：用户能管理"待处理 / 已处理 / 暂缓"工作流。

### 4.8 AI Prompt 升级

输入：当前 session 的全部记录。

处理：

1. 在 Prompt 中按类型分组：视觉、文案、交互、布局、数据、状态。
2. 同一组内按优先级（高 → 中 → 低）排序。
3. 每条记录展示：作用域（页面 / 元素 selector）、优先级、状态、交互态（如有）、评论、样式修改。
4. 在开头总览段加一行"共 N 条记录，含必改 X 条、建议 Y 条、备注 Z 条"。
5. `deferred` 默认仍然输出但标注"暂缓 / 仅供参考"，避免 AI 误把暂缓记录执行掉。

输出：AI 能按类型批量处理，并优先处理 high 优先级。

### 4.9 JSON Import / Export

输入：包含 V0.1 / V0.2 / V0.3 记录的 JSON。

处理：

1. V0.3 导出使用 `version: "0.3"`。
2. 导入兼容 `0.1` / `0.2` / `0.3` 三个版本：
   - V0.1 / V0.2 缺失字段时按默认值补齐：`category = "visual"`、`priority = "medium"`、`status` 保持原 `open`/`resolved`、`interactionState = null`、`scope = "element"`。
   - V0.1 的 `styleChanges` 默认 `[]`（沿用 V0.2 规则）。
   - `scope: "page"` 的记录不要求 element。
3. 导入后立即可编辑、删除、切换状态。
4. 不识别的字段值（例如未来引入的类型）被忽略并提示用户。

输出：JSON 可跨版本流通。

## 5. Non-goals

V0.3 不做：

1. 多排序键（V0.3 仅支持创建时间升序 + 按状态/类型筛选）。
2. 自定义类型 / 优先级 / 状态（取值固定）。
3. 评论历史栈、删除撤销。
4. @ 提及、协作、通知。
5. AI 自动分类（用户必须手动选）。
6. 把交互态变成可视化预览（点 hover 不会真的让页面变 hover）。
7. 改动 V0.2 的样式预览能力。

## 6. Requirements

### R1：保存带类型/优先级的评论

Given 用户已选中元素或处于页面评论模式  
When 用户在 CommentEditor 选择类型、优先级并保存  
Then 记录写入 session，含 `category`、`priority`、`status: "open"`、`interactionState`（如选）。

### R2：保存交互态评论

Given 用户已选中元素  
When 用户选择 `category = interaction`，并选择 `interactionState = hover`  
Then 记录保存时 `interactionState = "hover"`，Prompt 输出含"交互态：悬停"。

### R3：页面评论

Given 用户不选元素，直接展开页面评论区  
When 用户写入"整体节奏太挤"并保存  
Then 记录保存时 `scope = "page"`，`element = null`，列表中显示"页面评论"占位。

### R4：编辑记录

Given 列表中存在记录  
When 用户点击"编辑"修改评论文本、类型、优先级、状态、交互态  
Then 原记录被原地更新，`id`、`createdAt`、`element`、`styleChanges` 保留，`updatedAt` 刷新。

### R5：删除记录

Given 列表中存在记录  
When 用户点击"删除"并在二次确认中点击"确认删除"  
Then 记录从 session 永久移除；点击"取消"时不变。

### R6：状态切换

Given 列表中存在记录  
When 用户点击状态徽标并选择"已处理"  
Then 记录 `status` 变为 `resolved`，`updatedAt` 刷新；筛选为"待处理"时该记录隐藏，状态提示用户"已切换为已处理"。

### R7：筛选

Given 列表有多种类型和状态的记录  
When 用户选择"状态：待处理"或"类型：交互"  
Then 列表只展示匹配项，统计提示"共 N 条记录，当前显示 M 条"。

### R8：JSON 兼容

Given 用户导入 V0.1 或 V0.2 JSON  
When 解析完成  
Then 所有记录补齐 V0.3 默认元信息，仍可编辑、删除、切换状态。

### R9：Prompt 分组

Given 当前 session 含多种类型的记录  
When 用户点击复制 Prompt  
Then Prompt 中按"视觉 / 文案 / 交互 / 布局 / 数据 / 状态"分组，每组内按优先级排序，并标注总览统计。

## 7. User Stories

1. 作为产品经理，我希望把视觉问题和交互问题分开，这样开发能拆给不同的人。
2. 作为设计师，我希望对同一个按钮记录默认态和 hover 态两条记录，让开发不会漏。
3. 作为 AI 编程用户，我希望 Prompt 里有"必改"和"建议"两个清单，AI 优先处理必改。
4. 作为产品经理，我希望写错的评论能改，而不是删了重写。
5. 作为产品经理，我希望"整体页面有点拥挤"这种意见不需要先选元素。

## 8. Acceptance Criteria

1. `cd extension && npm run verify` 通过。
2. CommentEditor 中能选择类型、优先级；交互类型默认展开交互态下拉。
3. Panel 顶部能展开"页面评论"区，独立保存页面级记录。
4. 列表项展示类型 / 优先级 / 状态徽标，并支持"编辑"和"删除"。
5. 点击删除会弹出 Panel 内确认浮层，点击取消不删除。
6. 列表上方有"状态"和"类型"筛选，可正确过滤。
7. JSON 导出含 `version: "0.3"` 与所有新字段。
8. 导入 V0.1 / V0.2 JSON 全部补齐默认元信息且可编辑。
9. Prompt 内容按类型分组、按优先级排序，开头有总览。
10. V0.2 样式预览、保存、Prompt 样式段落仍正常。

## 9. Dependencies

1. 延续 V0.2 的 Content Script、Panel、Overlay、样式编辑器架构。
2. 不新增后端服务。
3. 不新增大型 UI 组件库（继续手写控件 + Shadow DOM）。
4. 删除确认浮层在 Panel Shadow DOM 内自绘，避免 `window.confirm` 弹宿主页面对话框。

## 10. Risks and Edge Cases

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 用户混淆 `category=state` 与 `interactionState` | 类型 vs 状态命名相似 | UI 上 `interactionState` 仅在 `interaction`/`state` 类型出现并加副文案"针对哪个状态" |
| 删除二次确认被误关 | 误删 | Panel 浮层先聚焦"取消"，用户必须明确点"删除"才生效 |
| 编辑过程中用户点了页面别的元素 | 误覆盖编辑目标 | 编辑模式下 click 不会切换 selectedElement，需点"取消编辑"先退出 |
| 导入 V0.2 JSON 后用户期望 `category` 全部精确 | 默认全是 `visual` | 在导入成功 toast 中提示"已导入 X 条记录，全部默认为视觉/中等优先级，可逐条编辑" |
| 状态切换让记录从当前筛选中消失 | 用户找不到刚切的记录 | 状态消息提示并提供"显示全部"快捷按钮 |
| Prompt 分组在记录极少时显得空 | 比如只 1 条 | 仅输出存在记录的分组，避免空标题 |
| `deferred` 记录被 AI 当作必改 | 误执行 | Prompt 中明确写"以下记录已被用户标记暂缓，仅供参考" |
| V0.1 JSON 中 `status` 已经是 `resolved` | 不兼容 V0.3 取值 | V0.1 / V0.2 中只有 `open`/`resolved`，不与 V0.3 冲突 |

## 11. Rollout Notes

V0.3 开发顺序：

1. 数据结构与导入导出兼容（含测试）。
2. CommentEditor 元信息控件。
3. 记录编辑模式 + 删除确认。
4. 页面级评论入口与作用域。
5. 列表筛选与状态切换。
6. Prompt 分组输出。
7. 测试页面与文档同步。

V0.3 完成后，再进入 V0.4 标尺测距。

## 12. Open Questions

V0.3 当前默认决策：

1. 删除采用硬删除 + 二次确认（已确认）。
2. 页面级评论用 Panel 顶部独立折叠区（已确认）。
3. `interactionState` 仅在 `interaction` 和 `state` 类型自动展开，其他类型可点"显示交互态"手动展开。
4. `deferred` 记录在 Prompt 中仍输出但带标记，不直接过滤。
5. 编辑模式禁用元素选中切换，避免误覆盖。
6. 不引入"标签 / Tag" 这种自定义维度，避免与类型重叠。
