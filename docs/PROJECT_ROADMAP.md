# Web Visual AI Editor Project Roadmap

## 1. 产品定位

Web Visual AI Editor 是一个面向 AI 编程和前端页面改稿场景的浏览器可视化编辑辅助插件。

它不是传统低代码平台，也不是完整设计工具。它的核心定位是：在真实网页上建立“可视化选择元素 -> 记录修改意图 -> 结构化导出 -> 交给 AI 或开发人员实现”的工作流。

产品关键词：

1. 任意网页可运行。
2. DOM 元素可选择。
3. 修改意见可结构化。
4. Prompt 和 JSON 可导出。
5. 面向 AI / Codex / 前端开发交接。
6. 优先本地可用，后续再考虑协作和云端。

产品边界：

1. V0.x 阶段优先做浏览器插件，不做独立 SaaS 后台。
2. V0.x 阶段优先做本地数据，不做多人实时协作。
3. V0.x 阶段优先辅助表达和交接，不承诺自动改代码。
4. V1.0 目标是稳定可用版本，不是全功能设计工具。

当前阶段状态：

1. V0.1 最小闭环已完成代码实现，并已通过用户手动验收反馈。
2. V0.2 样式编辑器代码实现已完成，并通过 `npm run verify`，等待 Chrome 手动验收。
3. V0.2 详细产品规格见 `docs/V0.2_STYLE_EDITOR_SPEC.md`。
4. V0.2 实现计划已执行完毕：`docs/superpowers/plans/2026-05-22-v0.2-style-editor.md`。
5. V0.3 评论增强已完成产品规格 `docs/V0.3_COMMENT_ENHANCEMENT_SPEC.md` 与可执行实施计划 `docs/superpowers/plans/2026-05-22-v0.3-comment-enhancement.md`，等待用户审批后开始代码实现。

## 2. 目标用户

| 用户 | 典型场景 | 主要痛点 | 产品要提供的能力 |
|---|---|---|---|
| AI 编程用户 | 用 Codex、Claude Code、Cursor 修改页面 | 很难描述“哪个元素怎么改” | 选择元素、记录意图、复制 AI Prompt |
| 产品经理 | 验收 AI 生成页面、业务后台、活动页 | 反馈分散在截图、文字和口头说明里 | 在网页上逐项标注并导出修改清单 |
| UI/UX 设计师 | 对真实网页做视觉和交互改稿 | DevTools 信息太技术化，交接不结构化 | 基于元素位置、文本、尺寸记录设计意见 |
| 前端开发者 | 接收产品/设计反馈并改代码 | 缺少 selector、上下文和验收标准 | 获得结构化 JSON 和可执行 Prompt |
| 独立开发者 | 快速迭代自己的网站或 AI 原型 | 页面问题多但记录成本高 | 本地轻量标注、批量导出、逐步修改 |

优先级：

1. 第一优先用户：AI 编程用户和独立开发者。
2. 第二优先用户：产品经理和 UI/UX 设计师。
3. 第三优先用户：团队内前端开发协作。

## 3. 核心价值

### 3.1 把模糊改稿变成结构化输入

用户不再只说“这个页面不好看”或“这个按钮改一下”，而是能输出：

1. 元素 selector。
2. 元素文本。
3. 元素位置和尺寸。
4. 当前页面 URL 和 viewport。
5. 明确评论和修改意图。

### 3.2 降低 AI 前端修改的沟通成本

AI 或前端开发人员可以拿到更接近实现层的上下文，减少反复追问：

1. 是哪个元素？
2. 在页面哪里？
3. 当前文案是什么？
4. 用户想改什么？
5. 修改记录有几条？

### 3.3 让真实网页成为可评论的产品稿

用户可以直接在网页上建立类似 Figma Comment 的反馈层，而不是依赖截图、口头说明或 DevTools。

### 3.4 建立从视觉反馈到代码实现的交接协议

JSON 和 Prompt 是产品的关键交接协议。插件最终应该让修改意见能被：

1. AI 编程工具理解。
2. 前端开发人员理解。
3. 后续版本重新导入和复查。
4. 自动化工具进一步处理。

## 4. 最终完整功能蓝图

完整功能蓝图按能力域组织，不代表一次性实现。

### 4.1 插件运行与编辑模式

1. Chrome Extension Manifest V3。
2. 点击插件按钮进入/退出编辑模式。
3. 页面注入 Overlay 和 Panel。
4. 支持任意普通网页。
5. 支持刷新后恢复本地草稿。
6. 支持编辑状态提示。
7. 支持不影响原网页正常操作的退出机制。

### 4.2 元素选择与识别

1. Hover DOM 高亮。
2. 点击选中 DOM。
3. 显示 tagName、id、className、selector、text、rect。
4. 生成稳定 selector。
5. 支持 selector 找不到时的兜底信息。
6. 支持点击记录定位元素。
7. 后续支持相似元素识别。
8. 后续支持共享元素和组件模式识别。

### 4.3 评论与修改记录

1. 给选中元素添加评论。
2. 支持修改意图、问题类型、优先级、状态。
3. 支持多条记录列表。
4. 支持记录定位。
5. 支持记录编辑和删除。
6. 支持交互说明，例如 hover、click、loading、empty、error 状态描述。
7. 支持页面级说明。

### 4.4 样式编辑器

1. 读取元素关键 computed style。
2. 支持颜色修改。
3. 支持字号、字重、行高、间距。
4. 支持宽高、内边距、外边距。
5. 支持圆角、边框、阴影。
6. 支持改动前后对比。
7. 支持导出样式差异。

### 4.5 标尺测距

1. 显示元素尺寸。
2. 显示元素间距。
3. 支持选中两个元素测距。
4. 支持与视口、父容器、邻近元素测距。
5. 支持把测距结果写入修改记录。

### 4.6 共享元素与相似组件

1. 检测相似 DOM 结构。
2. 检测相似 class / selector 模式。
3. 标记“应用到同类元素”。
4. 导出共享修改意图。
5. 后续为组件识别和批量修改提供基础。

### 4.7 自动布局辅助

1. 识别父子层级。
2. 识别 flex/grid 基础布局。
3. 推断元素排列方向、gap、对齐方式。
4. 支持用户记录“改成横向/纵向/居中/等距”等布局意图。
5. 导出布局相关 Prompt。

### 4.8 字体读取与切换

1. 读取当前元素 font-family。
2. 读取字号、字重、行高。
3. 支持本地可用字体列表。
4. 支持临时切换预览。
5. 支持导出字体修改记录。

### 4.9 导入导出与 AI 交接

1. JSON 导出。
2. JSON 导入。
3. 复制 AI Prompt。
4. 后续支持 Markdown 改稿清单。
5. 后续支持按 AI 工具生成不同 Prompt 模板。
6. 后续支持导出 CSS Patch 草案。
7. 后续支持导出任务清单。

### 4.10 稳定性、隐私与质量

1. 不默认采集整页 DOM。
2. 不读取敏感输入框 value。
3. 不上传数据到远程服务。
4. 支持本地草稿。
5. 支持导出前隐私提示。
6. 支持错误边界和降级提示。
7. 支持常见页面兼容测试。

## 5. 推荐版本路线图

### V0.1：最小闭环

目标：证明产品核心工作流可跑通。

功能边界：

1. Chrome Extension MV3 基础架构。
2. 点击插件按钮进入/退出编辑模式。
3. Hover DOM 高亮。
4. 点击 DOM 选中元素。
5. Panel 展示基础元素信息。
6. 支持添加评论。
7. 支持记录列表。
8. 支持点击记录定位元素。
9. 支持 JSON 导出。
10. 支持 JSON 导入。
11. 支持复制 AI Prompt。

不做：

1. 样式编辑器。
2. 标尺测距。
3. 相似组件识别。
4. 自动布局。
5. 字体切换。
6. 云端同步。

验收标准：

1. 插件可以在 Chrome 中加载。
2. 点击插件按钮后，当前网页进入编辑模式。
3. Hover 普通 DOM 元素时高亮框准确显示。
4. 点击元素后，Panel 展示 `tagName/id/className/selector/text/width/height/x/y`。
5. 用户可以保存至少 3 条评论记录。
6. 点击记录可以定位回对应元素。
7. 导出的 JSON 可再次导入。
8. 复制的 AI Prompt 包含页面信息和全部记录。
9. 退出编辑模式后，原网页交互恢复。
10. `npm run verify` 通过。

### V0.2：样式编辑器

目标：让用户能在页面上预览基础视觉调整，并把样式差异结构化导出。

功能边界：

1. 读取选中元素 computed style。
2. 展示颜色、字号、字重、行高、宽高、间距、圆角、边框、阴影。
3. 支持编辑基础样式并实时预览。
4. 支持记录“原值 -> 新值”。
5. JSON 中新增 styleChanges。
6. AI Prompt 中新增样式修改说明。

不做：

1. 自动生成生产级 CSS。
2. 跨组件批量样式修改。
3. 复杂响应式断点编辑。
4. 动画编辑器。

验收标准：

1. 选中元素后可以看到关键样式。
2. 修改颜色、字号、间距、圆角等基础样式后，页面可即时预览。
3. 每次样式修改能保存原值和新值。
4. 导出 JSON 包含 styleChanges。
5. 导入 JSON 后能恢复样式修改记录。
6. 复制 Prompt 时包含样式修改意图。
7. 退出编辑模式后可选择清除预览样式，不污染原页面。

### V0.3：评论与交互说明增强

目标：让记录不只描述静态视觉问题，也能描述交互状态和页面流程问题。

功能边界：

1. 评论支持类型：视觉、文案、交互、布局、数据、状态。
2. 评论支持优先级：低、中、高。
3. 评论支持状态：待处理、已处理、暂缓。
4. 支持编辑和删除评论。
5. 支持页面级评论。
6. 支持交互说明：hover、click、focus、loading、empty、error、disabled。
7. Prompt 按类型分组输出。

不做：

1. 多人协作。
2. 远程评论同步。
3. 审批流。
4. 通知系统。

验收标准：

1. 用户能为记录选择类型、优先级和状态。
2. 用户能编辑和删除已有记录。
3. 用户能添加页面级评论。
4. 用户能为同一元素记录不同交互状态的说明。
5. 导出 JSON 保留评论类型、优先级、状态和交互说明。
6. Prompt 能按记录类型清晰分组。

### V0.4：标尺测距

目标：补齐视觉走查中最常见的尺寸和间距表达问题。

功能边界：

1. 选中元素时显示宽高。
2. 支持元素与视口边缘测距。
3. 支持元素与父容器测距。
4. 支持选择两个元素测距。
5. 支持把测距结果保存到记录。
6. 支持导出测距信息到 JSON 和 Prompt。

不做：

1. 像素级设计稿对比。
2. 自动布局修复。
3. 多元素复杂网格分析。

验收标准：

1. 选中元素后能看到宽高。
2. 用户可以测量两个元素之间的水平/垂直距离。
3. 用户可以测量元素到父容器边缘的距离。
4. 测距结果可以附加到评论记录。
5. 导出的 JSON 和 Prompt 包含测距数据。
6. 页面滚动和 resize 后测距线位置正确更新。

### V0.5：共享元素 / 相似组件

目标：让用户表达“这类元素都要一起改”，减少重复标注。

功能边界：

1. 基于 tag、class、selector path 检测相似元素。
2. 支持显示候选相似元素数量。
3. 支持用户选择“仅当前元素”或“应用到相似元素”。
4. 支持记录 sharedGroup。
5. 支持批量定位和高亮相似元素。
6. Prompt 中说明批量修改范围。

不做：

1. 深度 React/Vue 组件识别。
2. AST 级代码组件映射。
3. 自动批量改代码。

验收标准：

1. 对列表项、按钮组、卡片组等常见结构能识别相似元素。
2. 用户能手动确认是否共享修改。
3. 批量记录能导出 sharedGroup 信息。
4. Prompt 能明确说明“应用到同类元素”的范围。
5. 用户能取消共享设置。

### V0.6：自动布局

目标：让插件能理解和表达基础布局关系，帮助 AI 更准确地改页面结构。

功能边界：

1. 识别选中元素的父容器。
2. 读取父容器 display、flex-direction、justify-content、align-items、gap。
3. 支持基础 flex/grid 信息展示。
4. 支持记录布局修改意图。
5. 支持布局建议 Prompt，例如“改为横向排列”“保持 16px gap”“居中对齐”。

不做：

1. 完整自动布局编辑器。
2. 复杂响应式规则推断。
3. 与 Figma Auto Layout 完全等价的模型。

验收标准：

1. 选中元素后能看到父容器基础布局信息。
2. flex 和 grid 常见场景能正确识别。
3. 用户能保存布局修改意图。
4. JSON 和 Prompt 能包含布局上下文。
5. 布局信息无法识别时有明确降级提示。

### V0.7：字体读取与切换

目标：支持文本视觉改稿中高频的字体、字号、字重和行高问题。

功能边界：

1. 读取选中元素字体信息。
2. 展示 font-family、font-size、font-weight、line-height、letter-spacing。
3. 支持输入或选择字体进行临时预览。
4. 支持保存字体修改记录。
5. 支持导出字体修改 JSON 和 Prompt。

不做：

1. 字体文件上传。
2. 云端字体管理。
3. 跨系统字体一致性保证。
4. 商用字体授权判断。

验收标准：

1. 文本元素能展示字体信息。
2. 字体预览不会破坏原页面结构。
3. 用户能记录字体修改前后值。
4. 导出 JSON 包含 fontChanges。
5. Prompt 能明确描述字体修改要求。
6. 无法读取或不可用字体时给出提示。

### V1.0：稳定可用版本

目标：将 V0.x 能力收口为稳定、可交付、可长期使用的本地插件版本。

功能边界：

1. 完整 V0.1 至 V0.7 核心能力收口。
2. 稳定的编辑模式启停。
3. 稳定的元素选择和定位。
4. 稳定的评论、样式、测距、字体、布局记录。
5. 稳定的 JSON 导入导出。
6. 稳定的 AI Prompt 模板。
7. 本地草稿恢复。
8. 隐私提示和导出检查。
9. 常见网页兼容性处理。
10. 完整错误提示和降级方案。

不做：

1. 多人实时协作。
2. 云端项目管理。
3. 自动提交代码。
4. 完整设计系统管理后台。
5. 完整 DevTools 替代品。

验收标准：

1. 插件能在至少 20 个真实网页场景中完成选择、记录、导出。
2. 核心流程无阻塞级错误。
3. JSON 版本兼容策略明确。
4. Prompt 能稳定服务 AI 编程改稿。
5. 编辑模式退出后不污染宿主页面。
6. 常见异常有明确提示：selector 找不到、导入失败、页面不支持、权限不足。
7. 隐私说明清晰，不默认上传数据。
8. 构建、类型检查、核心测试全部通过。
9. 文档和实现保持一致。

## 8. 路线图执行原则

1. 每个版本必须先完成当前版本验收，再进入下一个版本。
2. 不允许把后续版本功能提前塞入 V0.1，除非更新路线图并明确原因。
3. 每个版本都必须同步更新 `docs/DEVELOPMENT_PLAN.md` 和 `docs/ACCEPTANCE_CRITERIA.md`。
4. 涉及数据结构变化时，必须同步更新 `docs/DATA_FORMAT.md`。
5. 涉及架构变化时，必须同步更新 `docs/TECH_ARCHITECTURE.md`。
