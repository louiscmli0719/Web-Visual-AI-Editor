# Web Visual AI Editor V0.5 Shared Elements Spec

当前实现状态（2026-05-23）：代码闭环已接入并通过自动验证，包含相似识别、批量高亮、批量记录、JSON/Prompt 输出和验收样本；仍待 Chrome 手动验收。

## 1. Problem / Opportunity

V0.1–V0.4 已经把"选元素 → 评论 → 样式预览 → 测距 → 结构化导出"的闭环跑通了，但每一条记录都是**针对单个元素**的。在真实改稿场景下，很多反馈天然适用于"一组同类元素"：

1. "所有卡片标题字号要小一档" — 用户得重复选 8 张卡片、写 8 条评论。
2. "导航栏每个链接 hover 时要变蓝" — 用户得给每个链接保存一次记录。
3. "列表项之间间距 16px" — 用户得选中所有列表项逐个标。

V0.5 的机会：在用户选中元素后，**识别相似元素**并允许用户一键标记"应用到同类"，让一条记录代表一组目标。AI / 开发拿到 Prompt 后就能批量修改，而不是逐条对应。

## 2. Goal and Success Metrics

目标：在 V0.4 的元素选择、评论、样式、测距体系上，增加相似元素识别和共享分组能力。一条记录可以选择"仅当前元素"或"应用到 N 个相似元素"。导出 JSON 和 Prompt 完整保留分组范围。

成功标准：

1. 用户选中元素后，Panel 显示"相似元素：N 个"（基于 tag + class 启发式）。
2. 用户可以预览相似元素（hover Panel 中的 selector 列表，对应元素在页面上闪烁）。
3. 用户可以勾选"应用到相似元素"，保存记录时附 `sharedGroup` 数据。
4. 用户可以在记录列表上看到"批量记录"标识和目标数量。
5. 导出 JSON 包含 `sharedGroup` 字段。
6. AI Prompt 中清楚标注"以下记录适用于 N 个相似元素：…"。
7. 用户可以在 Overlay 上同时高亮所有相似元素（批量定位）。
8. V0.4 的测距、V0.3 的评论分组、V0.2 的样式预览闭环不被破坏。

## 3. Target Users and Main Scenarios

| 用户 | 场景 | V0.5 要解决的问题 |
|---|---|---|
| AI 编程用户 | 让 AI 批量调整一组组件 | Prompt 中明确"应用到这 8 个 `.card-title`"，AI 一次性改 |
| 产品经理 | 验收多个列表项 | 一条评论覆盖整组而不是 8 条重复 |
| UI/UX 设计师 | 改卡片 / 按钮组 / 导航的整组视觉 | 选中一个就能标记整组，省去 N-1 次操作 |
| 前端开发者 | 接收"全局微调"类反馈 | 知道修改范围是组件级而非实例级 |

## 4. Scope

### 4.1 相似元素识别算法

输入：当前选中元素。

处理（按优先级匹配，三级降级）：

1. **第一级（精确）**：tag + 完整 class list（顺序无关）匹配。例：`button.btn.primary` 匹配所有同 tag 同 class 集合的元素。
2. **第二级（class 主特征）**：tag + class 前缀匹配。取选中元素 class 中**最长的一个**作为主特征，匹配同 tag 同主 class 的元素。例：选中 `<button class="btn btn-primary">`，主特征 `btn-primary`，匹配所有同 tag 且含 `btn-primary` 的元素。
3. **第三级（结构）**：仅 tag 匹配，但限制：父容器有相同 tag（典型场景：列表项 `<li>` 同一 `<ul>` 下）。

输出：相似元素的 `Element[]` 列表，附识别级别（用于 UI 标注质量）。

降级规则：

- 选中元素无 class 时跳过 1、2 级，直接用 3 级。
- 1 级匹配数 ≥2 时直接使用 1 级；否则尝试 2 级；否则 3 级。
- 任何级别匹配总数（含选中元素自身）不超过 50 个，超过时截断并提示用户"超过 50 个，仅显示前 50"。
- 排除插件自身 DOM（panel / overlay）。

### 4.2 Panel 相似元素入口

输入：当前选中元素 + 相似元素列表。

处理：

1. 在 ElementInfoPanel 下方新增"相似元素"区块，默认折叠。
2. 折叠状态下显示徽标：`相似元素：N 个（精确 / class 主特征 / 仅 tag）`。
3. 展开后显示前 10 个相似元素的 selector 列表 + "查看全部 N 个"按钮。
4. 鼠标 hover 列表项时，对应元素在页面 Overlay 上闪烁。
5. 提供"高亮全部"按钮：点击后 Overlay 同时显示所有相似元素的虚线轮廓（持续 3 秒后自动消失）。
6. 提供"应用到相似元素"复选框，默认未勾选。

输出：用户能清楚理解"会影响哪些元素"。

### 4.3 SharedGroup 数据

```ts
type SharedGroup = {
  matchLevel: "exact" | "class-primary" | "tag-only";
  primaryFeature: string;       // 主匹配特征，例如 ".btn-primary" 或 "li"
  totalMatched: number;          // 已纳入范围的目标数（含自身，最多 50）
  truncated: boolean;            // 是否被 50 上限截断
  targets: ElementSnapshot[];    // 所有相似元素快照（不含当前元素，避免重复）
};
```

字段说明：

| 字段 | 说明 |
|---|---|
| `matchLevel` | 匹配级别，决定 UI 显示的"精度"标识 |
| `primaryFeature` | 用于在 Prompt 中标识共享范围（"应用到所有 .btn-primary"） |
| `totalMatched` | 已纳入当前范围的目标数量（含当前元素，上限 50）；`truncated: true` 表示页面还存在未纳入的匹配目标 |
| `truncated` | true 时 AI 应注意可能漏掉部分元素 |
| `targets` | 每个相似元素的完整快照（包含 selector / text / rect） |

### 4.4 EditRecord 扩展

```ts
type EditRecord = {
  // ... V0.4 fields
  sharedGroup: SharedGroup | null;  // V0.5 新增
};
```

- `sharedGroup === null`：单元素记录（V0.1–V0.4 行为）。
- `sharedGroup !== null`：共享记录，AI 应将修改应用到 `sharedGroup.targets` 中所有元素 + 当前 `element`。

V0.4 / V0.3 / V0.2 / V0.1 JSON 导入时默认补 `sharedGroup: null`。

### 4.5 CommentEditor 升级

输入：当前选中元素 + 识别到的相似元素列表。

处理：

1. 在"附加测距数据"复选框旁新增"应用到相似元素（N 个）"复选框。
2. 仅在 N ≥ 1（即识别到至少一个相似元素）时显示；否则隐藏（无意义）。
3. 默认未勾选，保留用户上次选择？**V0.5 决策：不保留**，每次新建记录默认未勾选，避免误触。
4. 勾选后保存的记录附 `sharedGroup` 数据快照（保存时刻的相似元素列表）。
5. 编辑现有记录时，复选框默认状态 = 记录 `sharedGroup !== null`。
6. 编辑时可重新勾选/取消，保存后 sharedGroup 用编辑时的快照重新生成（基于编辑时刻的 selectedElement 重新识别）。

输出：用户能用一次保存覆盖整组元素。

### 4.6 RecordList 升级

输入：所有记录。

处理：

1. 共享记录在列表项中显示徽标"批量 × N"（N = totalMatched）。
2. 徽标可点击：点击后 Overlay 高亮所有相似元素（与"高亮全部"按钮相同）3 秒。
3. 截断的（truncated = true）记录额外显示"已截断"小标。
4. 筛选条增加"范围"维度：全部 / 单元素 / 批量。

输出：用户能在列表中区分单元素和批量记录。

### 4.7 Overlay 共享元素渲染

输入：sharedGroup.targets 的 rects。

处理：

1. 提供 `highlightSimilarElements(rects: Rect[])` 接口。
2. Overlay 用半透明虚线框（颜色 #fb7185 红粉色，区别于选中框的强红和测距线的红色）渲染每个相似元素。
3. 3 秒后自动淡出（透明度过渡 600ms）。
4. 不阻塞用户点击宿主页面。

输出：用户能可视化批量范围。

### 4.8 AI Prompt 升级

输入：每条带 `sharedGroup` 的记录。

处理：

1. 共享记录的"用户评论 / 修改意图"段落后新增"作用范围："子段落：
   ```
   作用范围：以下修改请应用到 {N} 个相似元素（匹配级别：{级别说明}）：
   - {selector 1}
   - {selector 2}
   ...
   - {selector M}
   {如果 truncated} 注意：识别到超过 50 个相似元素，已截断为 50 个，可能漏掉部分。
   ```
2. matchLevel 中文映射：
   - `exact` → 精确匹配（tag + 完整 class）
   - `class-primary` → 主类匹配（同 tag + 同主类）
   - `tag-only` → 结构匹配（同父容器同 tag）
3. 单元素记录（sharedGroup === null）不输出此段。
4. 总览段不区分单元素和共享记录数（只按优先级统计）。

### 4.9 JSON Import / Export

1. V0.5 导出 `version: "0.5"`。
2. 导入 V0.1 / V0.2 / V0.3 / V0.4 JSON：所有记录补 `sharedGroup: null`。
3. 导入 V0.5 JSON：`sharedGroup` 完整保留，不重新匹配（避免页面结构变化后误改范围）。
4. 页面级记录导入后强制清除元素专属字段（`element`、`interactionState`、`styleChanges`、`measurements`、`sharedGroup`），元素级记录缺失合法 `element` 时拒绝导入。

### 4.10 退出编辑模式清理

1. 清除"高亮全部"残留的 Overlay 虚线框。
2. 清空相似元素折叠状态。

## 5. Non-goals

V0.5 不做：

1. React / Vue / Svelte 组件识别（不读 framework runtime）。
2. AST 级代码映射。
3. 自动批量改代码 / 自动应用样式预览到所有相似元素。
4. 跨页面 / 跨 tab 的共享分组。
5. 用户自定义匹配规则（如"匹配所有 data-role=card 的元素"）。
6. 同时保存多个 sharedGroup（每条记录最多一个）。
7. 共享分组与样式预览实时联动（V0.5 不在所有相似元素上预览样式变化，避免性能 / 副作用问题；预览仍只作用于当前元素）。
8. 共享分组与双元素测距联动（pair 仍是 1 对 1）。

## 6. Requirements

### R1：识别相似元素

Given 用户已选中元素
When Panel 更新
Then Panel 显示"相似元素：N 个"和匹配级别徽标

通过标准：

1. N 包含当前元素，但 targets 不包含当前元素（targets 长度 = N - 1）。
2. 匹配级别按 1 → 2 → 3 自动降级。
3. 超过 50 个时截断，显示 truncated 标识。

### R2：预览相似元素

Given 相似元素区块已展开
When 用户 hover selector 列表项
Then 对应元素在页面上闪烁（reuse V0.1 flash 机制）

### R3：高亮全部

Given 用户点击"高亮全部"按钮
When Overlay 接收到 highlightSimilarElements
Then 所有相似元素的虚线框（含当前元素）3 秒内可见，3.6 秒后完全消失

### R4：保存共享记录

Given 用户在 CommentEditor 勾选"应用到相似元素"
When 用户保存
Then 记录 sharedGroup 字段写入 targets 数组和 matchLevel

通过标准：

1. 复选框未勾选时 sharedGroup = null。
2. 复选框勾选时 sharedGroup.targets 包含识别时刻的所有相似元素快照（不含当前元素）。
3. 保存后 CommentEditor 复选框重置为未勾选。

### R5：编辑共享记录

Given 列表中有共享记录
When 用户编辑该记录
Then CommentEditor 复选框默认勾选，初始相似元素列表来自当前选中元素（不是记录里的旧 targets）

通过标准：

1. 重新保存后 sharedGroup.targets 基于编辑时刻重新识别。
2. 取消勾选保存后 sharedGroup = null。

### R6：RecordList 徽标 + 筛选

Given 列表中有共享记录和单元素记录
When Panel 渲染
Then 共享记录显示"批量 × N"徽标，截断的额外显示"已截断"

通过标准：

1. 筛选"范围：批量"只显示共享记录。
2. 筛选"范围：单元素"只显示非共享记录。
3. 点击徽标在 Overlay 高亮所有 targets。

### R7：Prompt 输出

Given session 中有共享记录
When 用户复制 Prompt
Then 共享记录附"作用范围："子段落

通过标准：

1. 单元素记录不输出此段。
2. truncated 时输出额外提示。
3. matchLevel 显示中文标签。

### R8：JSON 兼容

Given 用户导入 V0.1–V0.4 JSON
When 解析完成
Then 所有记录 sharedGroup 默认 null

### R9：退出清理

Given 用户处于编辑模式，Overlay 显示"高亮全部"
When 用户退出编辑模式
Then Overlay 清空，无残留虚线框

## 7. User Stories

1. 作为产品经理，我想说"所有卡片标题字号要小一档"，一次保存就覆盖 8 张卡片。
2. 作为 UI 设计师，我想看到"这个 .btn-primary 在页面上一共有 12 个"，避免漏改。
3. 作为 AI 编程用户，我想 Prompt 告诉 AI"以下样式改 .card-title 这个 class 即可，不必查 12 处"。
4. 作为前端开发者，我想知道改动范围是"实例级"还是"组件级"，避免改错位。

## 8. Acceptance Criteria

1. `cd extension && npm run verify` 通过。
2. Panel 显示相似元素数量和匹配级别。
3. 展开相似元素列表，hover 列表项时对应元素闪烁。
4. 点击"高亮全部"，Overlay 显示所有相似元素 3 秒。
5. 勾选"应用到相似元素"保存记录，记录 sharedGroup 写入。
6. RecordList 显示"批量 × N"徽标，可筛选。
7. 导出 JSON 含 `version: "0.5"` 和 sharedGroup 字段。
8. 导入 V0.1–V0.4 JSON 全部补 sharedGroup: null。
9. Prompt 中共享记录含"作用范围："子段落。
10. 退出编辑模式无残留。
11. V0.4 测距、V0.3 评论分组、V0.2 样式预览不被破坏。

## 9. Dependencies

1. 延续 V0.4 架构。
2. 新增 `content/similar-elements.ts` 纯函数模块（识别算法）。
3. Overlay 新增"批量高亮层"渲染（在现有 overlay-root.ts 内扩展）。
4. 不新增后端、不新增 UI 库。

## 10. Risks and Edge Cases

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 算法误识别（把不该一起改的当成相似） | 用户保存后批量范围错误 | UI 必须清晰显示 targets 列表，让用户预览后再勾选 |
| 算法漏识别（同类元素 class 不一致） | 用户得手动多次保存 | 提供"高亮全部"按钮帮用户校对，未来可加自定义匹配规则 |
| 相似元素超过 50 | 列表过长、Overlay 渲染卡顿 | 截断到 50 + 显式提示 |
| 用户编辑共享记录时页面已变化 | 旧 sharedGroup 不匹配 | 编辑模式重新识别（用最新状态），不复用旧 targets |
| 共享记录的样式预览 | 只作用于当前元素，AI 可能误以为预览数值仅对单元素生效 | Prompt 明确写"作用范围"，且 V0.5 文档说明预览不与共享分组联动 |
| 已截断的记录被 AI 当作完整集合 | AI 漏改部分元素 | Prompt 中明确写出 truncated 警告 |
| 选中元素是插件自身 DOM | 算法可能匹配到 panel 内部 | 识别算法 root 始终为 document.body，并排除带 `wvaie-` ID 前缀的容器 |
| 性能：50 个元素 querySelectorAll 在大型页面是否卡 | 用户感知延迟 | 识别在 selectElement 时同步进行；50 上限已限制；测量本地常见页面 < 20ms 即可接受 |

## 11. Rollout Notes

V0.5 开发顺序：

1. 数据结构 + JSON 兼容（含测试）。
2. similar-elements.ts 纯函数 + 测试。
3. Overlay 批量高亮层。
4. Panel 相似元素区块（折叠 + hover 预览 + 高亮全部）。
5. CommentEditor "应用到相似元素" 复选框。
6. RecordList 徽标 + 范围筛选。
7. Prompt "作用范围" 子段落。
8. 测试页面（含明显的相似元素群组：卡片组、按钮组、列表项）。
9. 文档同步。

V0.5 完成后，进入 V0.6 自动布局。
