# Web Visual AI Editor Product Spec

## 1. 产品目标

Web Visual AI Editor 是一个运行在任意网页上的可视化改稿与评论 Chrome 插件。用户可以像使用 Figma / VisBug 一样，直接在网页中选择元素、查看元素信息、添加评论、记录修改内容，并最终把编辑内容导出为 AI Prompt 或 JSON。

V0.1 的目标不是直接改网页样式，而是解决“我无法准确描述哪个元素需要怎么改”的问题。

项目总目标、完整功能蓝图和 V0.1 至 V1.0 版本路线图见 `docs/PROJECT_ROADMAP.md`。本文档主要约束 V0.1 MVP 产品规格，避免把后续版本能力提前混入最小闭环。

当前状态：

1. V0.1 已完成代码实现，并已通过用户手动验收反馈。
2. V0.2 样式编辑器已完成代码实现，并通过 `npm run verify`，等待 Chrome 手动验收，详细规格见 `docs/V0.2_STYLE_EDITOR_SPEC.md`。
3. V0.3 评论增强已完成产品规格 `docs/V0.3_COMMENT_ENHANCEMENT_SPEC.md` 与可执行实施计划 `docs/superpowers/plans/2026-05-22-v0.3-comment-enhancement.md`，等待用户审批。
4. V0.2 / V0.3 不改写本文档的 V0.1 MVP 范围，而是在独立规格中定义增量能力。

V0.1 要跑通的最小闭环：

1. 进入编辑模式。
2. 选择网页元素。
3. 查看元素基础信息。
4. 添加评论或修改意图。
5. 汇总当前页面修改记录。
6. 导出 JSON。
7. 导入 JSON。
8. 复制 AI Prompt。

## 2. 核心用户

| 用户 | 使用场景 | 主要诉求 |
|---|---|---|
| AI 编程用户 | 用 Codex、Claude Code、Cursor 等工具改前端页面 | 准确描述页面哪里要改、怎么改 |
| 产品经理 | 评审前端页面或 AI 生成页面 | 不打开 DevTools 也能标注问题 |
| UI/UX 设计师 | 对线上页面或原型页面做改稿意见 | 把视觉和交互意见结构化交给开发 |
| 前端开发者 | 接收非技术角色的页面反馈 | 获得 selector、位置、文本和评论 |

## 3. 核心用户流程

1. 用户打开一个网页。
2. 用户点击 Chrome 插件图标。
3. 插件将当前网页切换为编辑模式。
4. 用户移动鼠标，页面 DOM 元素出现 hover 高亮框。
5. 用户点击目标元素。
6. 插件选中该元素，并在面板中展示元素基础信息。
7. 用户输入评论或修改意图。
8. 用户保存记录。
9. 插件把记录加入当前页面配置列表。
10. 用户继续选择其他元素并添加记录。
11. 用户点击某条记录，页面定位到对应元素。
12. 用户导出 JSON 或复制 AI Prompt。
13. 用户把 Prompt 发给 AI / Codex / 前端开发人员。

## 4. MVP V0.1 功能边界

### 4.1 Chrome 插件基础架构

输入：用户安装插件并点击插件图标。

处理：

1. Background Service Worker 接收点击事件。
2. 对当前 tab 注入 Content Script。
3. 切换当前页面的编辑模式状态。

输出：当前网页进入或退出编辑模式。

### 4.2 编辑模式

输入：插件启动命令。

处理：

1. Content Script 初始化 Overlay 和 Panel。
2. 添加 hover、click、scroll、resize 监听。
3. 标记当前页面处于编辑状态。

输出：

1. 页面右侧出现插件面板。
2. 鼠标移动时可高亮 DOM 元素。

### 4.3 Hover DOM 高亮

输入：鼠标移动事件。

处理：

1. 使用 `event.target` 获取当前 DOM 元素。
2. 排除插件自身 UI。
3. 读取元素 `getBoundingClientRect()`。
4. Overlay 绘制 hover 高亮框。

输出：目标元素周围显示 hover 边框。

### 4.4 点击选中元素

输入：用户点击页面 DOM 元素。

处理：

1. 阻止原页面点击默认行为。
2. 生成元素快照。
3. 生成稳定 selector。
4. 更新 selected 状态。
5. Overlay 绘制 selected 高亮框。

输出：面板展示选中元素信息。

### 4.5 元素信息展示

输入：选中的 DOM Element。

处理：

1. 读取 `tagName`。
2. 读取 `id`。
3. 读取 `className`。
4. 生成 `selector`。
5. 读取并裁剪 `textContent`。
6. 读取 `width`、`height`、`x`、`y`。

输出：面板展示元素基础信息。

### 4.6 添加评论

输入：选中元素和用户输入的评论。

处理：

1. 校验当前是否有选中元素。
2. 校验评论是否非空。
3. 生成 `EditRecord`。
4. 写入当前页面 session。
5. 更新记录列表。

输出：评论记录保存成功。

### 4.7 配置列表

输入：当前页面全部 `EditRecord`。

处理：

1. 按创建时间排序。
2. 显示元素摘要、selector、评论内容和状态。
3. 支持点击定位。

输出：用户能看到当前页面所有评论和修改记录。

### 4.8 点击记录定位元素

输入：用户点击记录列表中的某条记录。

处理：

1. 使用 `selector` 查找 DOM 元素。
2. 如果找到，滚动到视口中心。
3. 更新 selected 状态。
4. Overlay 显示定位高亮。
5. 如果找不到，显示未匹配状态。

输出：页面定位到对应元素，或提示当前页面未匹配到元素。

### 4.9 JSON 导出

输入：当前 `EditorSession`。

处理：

1. 序列化页面信息和记录列表。
2. 写入 `app`、`version`、`exportedAt`。
3. 生成 JSON 文件或复制 JSON 文本。

输出：用户获得可保存、可导入、可发给 AI 的 JSON。

### 4.10 JSON 导入

输入：用户选择或粘贴 JSON。

处理：

1. 解析 JSON。
2. 校验 `app` 和 `version`。
3. 校验 `records` 基础字段。
4. 恢复记录列表。
5. 尝试用 selector 匹配当前页面 DOM。

输出：记录列表恢复；无法匹配的记录保留并提示。

### 4.11 复制 AI Prompt

输入：当前页面信息和记录列表。

处理：

1. 使用 Prompt 模板生成自然语言说明。
2. 嵌入 selector、元素信息、位置、文本和评论。
3. 调用剪贴板 API。

输出：用户剪贴板中获得 AI 可读的改稿 Prompt。

## 5. 非 MVP 暂缓功能

V0.1 明确不做：

1. 样式编辑器。
2. 可视化拖拽修改样式。
3. 共享元素。
4. 本地字体读取。
5. 自动布局推断。
6. 标尺测距。
7. React / Vue 组件识别。
8. 云端同步。
9. 多人协作。
10. AI 自动改代码。
11. 自动生成 CSS Patch。
12. DevTools Panel。
13. iframe 深度编辑。
14. Shadow DOM 深度解析。

## 6. 成功标准

1. 用户能在任意普通网页上进入编辑模式。
2. 用户能选中 DOM 元素并查看基础信息。
3. 用户能添加至少一条评论记录。
4. 用户能导出 JSON。
5. 用户能导入 JSON 恢复记录。
6. 用户能复制 AI Prompt。
7. 用户退出编辑模式后，原网页交互不受影响。
