# Web Visual AI Editor V0.2 Style Editor Spec

## 1. Problem / Opportunity

V0.1 已经跑通“选中元素 -> 添加评论 -> 导出 JSON / Prompt”的闭环，但用户仍然只能用文字描述视觉修改。对于常见前端改稿，很多反馈其实是明确的样式变化，例如颜色、字号、间距、圆角、边框和阴影。

V0.2 的机会是：让用户在真实网页上对选中元素做基础视觉预览，并把“原值 -> 新值”的差异结构化保存到记录里。

V0.2 不是完整样式编辑器，也不生成生产级 CSS。它只解决最常见、最容易表达、最适合 AI / 前端接收的样式改稿输入。

## 2. Goal and Success Metrics

目标：在 V0.1 的元素选择和记录体系上，增加基础样式读取、临时预览、样式差异保存、JSON / Prompt 导出能力。

成功标准：

1. 用户选中元素后，能看到关键 computed style。
2. 用户修改基础样式后，页面能即时预览。
3. 用户能撤销当前元素未保存的样式预览。
4. 用户保存记录后，记录中包含样式差异。
5. JSON 导出包含 `styleChanges`。
6. JSON 导入能恢复包含样式差异的记录。
7. AI Prompt 能清楚描述每条样式变化。
8. 退出编辑模式时，未保存和已保存的预览样式都不会永久污染原页面。

## 3. Target Users and Main Scenarios

| 用户 | 场景 | V0.2 要解决的问题 |
|---|---|---|
| AI 编程用户 | 对 AI 生成页面做视觉微调 | 不只说“更好看”，而是给出颜色、字号、间距等具体差异 |
| 产品经理 | 验收页面视觉层级 | 能用简单控件表达主次、大小、边距和按钮视觉权重 |
| UI/UX 设计师 | 对真实网页做改稿意见 | 能快速预览基础样式变化并导出给开发 |
| 前端开发者 | 接收改稿记录 | 能看到 selector、原样式、新样式和用户意图 |

## 4. Scope

### 4.1 Style Inspector

输入：当前选中的 DOM Element。

处理：

1. 使用 `getComputedStyle(element)` 读取样式。
2. 只读取 V0.2 支持的白名单属性。
3. 把属性转换为可展示的 `StylePropertySnapshot`。
4. 保留原始 computed value，作为后续差异比较基准。

输出：Panel 中展示选中元素的样式信息。

V0.2 支持属性：

| 分组 | 属性 |
|---|---|
| Color | `color`, `backgroundColor` |
| Typography | `fontSize`, `fontWeight`, `lineHeight` |
| Spacing | `paddingTop`, `paddingRight`, `paddingBottom`, `paddingLeft`, `marginTop`, `marginRight`, `marginBottom`, `marginLeft` |
| Shape | `borderRadius`, `borderWidth`, `borderColor` |
| Effect | `boxShadow` |

### 4.2 Style Controls

输入：用户在 Panel 中修改样式字段。

处理：

1. 校验属性是否在 V0.2 白名单内。
2. 校验输入格式是否可作为 CSS 值应用。
3. 写入当前元素的 preview inline style。
4. 更新当前元素的 `StyleDraft`。

输出：页面元素即时预览修改效果。

控件要求：

| 属性类型 | 控件 |
---|---|
| color / backgroundColor / borderColor | 文本输入 + 原生 color input |
| fontSize / lineHeight / spacing / borderRadius / borderWidth | number input + px 单位 |
| fontWeight | select：`400`, `500`, `600`, `700` |
| boxShadow | 文本输入 |

### 4.3 Preview Apply and Reset

输入：当前元素和用户修改后的样式值。

处理：

1. 首次修改某个属性时，记录该元素原始 inline style 值。
2. 把新值写入 `HTMLElement.style[property]`。
3. 用户点击“重置预览”时，恢复该元素被修改属性的原始 inline style。
4. 切换选中元素时，保留当前页面 preview，但 Panel 切换到新元素样式。
5. 退出编辑模式时，清除所有 preview inline style。

输出：预览可见，但不会永久污染页面。

### 4.4 Save Style Changes

输入：选中元素、当前评论、当前样式 draft。

处理：

1. 对比原始 computed style 和当前 draft。
2. 只保留发生变化的属性。
3. 生成 `StyleChange[]`。
4. 写入新的 `EditRecord.styleChanges`。
5. 如果评论为空但存在 style changes，允许保存记录。
6. 如果评论为空且没有 style changes，不允许保存。

输出：记录列表展示评论和样式差异。

### 4.5 Record List Display

输入：`EditRecord[]`。

处理：

1. 继续展示 selector 和 comment。
2. 如果存在 `styleChanges`，展示样式变化摘要。
3. 每条样式变化展示 `property: oldValue -> newValue`。

输出：用户能在记录列表里看到具体样式改动。

### 4.6 JSON Import / Export

输入：包含或不包含 `styleChanges` 的记录。

处理：

1. V0.2 导出使用 `version: "0.2"`。
2. 导出每条记录的 `styleChanges`。
3. 导入时兼容 V0.1：没有 `styleChanges` 的记录按评论记录处理。
4. 导入 V0.2 时恢复记录列表，但不自动把样式写入页面。

输出：JSON 可用于保存、迁移和 AI 交接。

### 4.7 AI Prompt

输入：包含 `styleChanges` 的 `EditorSession`。

处理：

1. 在每条记录中继续输出 selector、元素文本、位置和评论。
2. 如果存在样式变化，追加样式差异列表。
3. 明确提示 AI 优先结合现有样式系统实现，不要机械写 inline style。

输出：AI / Codex 可读的样式改稿 Prompt。

## 5. Non-goals

V0.2 不做：

1. 自动生成生产级 CSS Patch。
2. 自动定位源码文件。
3. 复杂 CSS 简写解析器。
4. 断点和响应式样式编辑。
5. 伪类样式编辑，例如 `:hover`、`:focus`。
6. 动画和 transition 编辑。
7. class 批量替换。
8. 相似组件批量应用。
9. 读取本地字体列表。
10. DevTools 面板。

## 6. Requirements

### R1：样式读取

Given 用户选中一个普通 DOM 元素  
When Panel 更新  
Then Panel 展示 V0.2 白名单属性的 computed style

### R2：样式编辑

Given 用户已选中元素  
When 用户修改受支持样式值  
Then 页面元素即时显示预览效果

### R3：样式差异

Given 用户修改了一个或多个样式  
When 用户保存记录  
Then 记录中包含每个属性的原值和新值

### R4：重置预览

Given 用户已经修改当前元素样式  
When 用户点击“重置预览”  
Then 当前元素恢复修改前的 inline style 状态

### R5：退出清理

Given 页面存在样式预览  
When 用户退出编辑模式  
Then 插件清除所有 preview inline style

### R6：导出兼容

Given 当前页面包含 V0.2 样式记录  
When 用户导出 JSON  
Then JSON 包含 `styleChanges`

### R7：导入兼容

Given 用户导入 V0.1 JSON  
When 插件解析记录  
Then 记录可以正常显示，`styleChanges` 默认为空数组

### R8：Prompt 输出

Given 当前记录包含样式变化  
When 用户复制 AI Prompt  
Then Prompt 包含样式差异和实现提示

## 7. User Stories

1. 作为 AI 编程用户，我想选中按钮后修改背景色和圆角，这样我能把更明确的视觉意图交给 Codex。
2. 作为产品经理，我想把标题字号调小并保存记录，这样开发能准确知道视觉层级要怎么改。
3. 作为设计师，我想看到原始颜色和修改后的颜色，这样改稿记录不会只停留在主观描述。
4. 作为前端开发者，我想在 Prompt 里看到 selector、原值、新值和评论，这样我能快速定位实现位置。

## 8. Acceptance Criteria

1. `npm run verify` 通过。
2. 选中元素后，Panel 展示样式编辑区域。
3. 修改 `backgroundColor` 后，页面元素即时变色。
4. 修改 `fontSize` 后，页面元素字号即时变化。
5. 修改 `borderRadius` 后，页面元素圆角即时变化。
6. 点击“重置预览”后，当前元素样式恢复。
7. 保存记录后，记录列表显示样式差异。
8. 导出 JSON 后，记录中包含 `styleChanges`。
9. 导入 V0.1 JSON 不报错。
10. 复制 Prompt 后，文本包含样式差异。
11. 退出编辑模式后，页面不保留插件写入的 preview inline style。

## 9. Dependencies

1. 延续 V0.1 的 Content Script、Panel、Overlay 架构。
2. 延续 Shadow DOM 隔离策略。
3. 不新增后端服务。
4. 不新增大型 UI 组件库。
5. 使用浏览器原生 `getComputedStyle` 和 `HTMLElement.style`。

## 10. Risks and Edge Cases

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 部分元素不是 HTMLElement | 无法写入 inline style | Panel 显示“该元素暂不支持样式预览” |
| CSS 值格式复杂 | 用户输入可能无效 | 只对简单属性提供结构化控件，复杂属性用文本输入 |
| `line-height: normal` | number 控件无法表达 | 保留原值展示，用户修改后用 px |
| margin 修改影响页面布局 | 可能造成页面跳动 | 只作为临时预览，退出时清除 |
| 样式来自 CSS 变量 | computed style 只显示最终值 | V0.2 记录最终值，不尝试反推 token |
| iframe / Shadow DOM 内部元素 | 读取和写入受限 | 延续 V0.1 降级策略，只处理当前可访问元素 |
| 导入 V0.2 JSON 到旧版本 | 旧版本不识别 styleChanges | 数据版本升级到 0.2，并保留 V0.1 兼容导入 |

## 11. Rollout Notes

V0.2 开发顺序：

1. 先做数据结构和测试。
2. 再做 computed style 读取。
3. 再做 preview manager。
4. 再做 Panel 控件。
5. 最后接入 JSON / Prompt 和人工验收。

V0.2 完成后，再进入 V0.3 评论类型、优先级、交互状态说明。

## 12. Open Questions

当前默认决策：

1. V0.2 只支持 px 数值编辑，不处理 rem / em / % 的双向转换。
2. V0.2 导入 JSON 后只恢复记录，不自动应用样式到页面。
3. V0.2 保存记录时，评论可以为空，但必须至少存在一条样式变化。
4. V0.2 不做样式历史撤销栈，只做当前元素“重置预览”和退出统一清理。
