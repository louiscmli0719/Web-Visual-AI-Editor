# Web Visual AI Editor V0.4 Ruler & Measurement Spec

## 1. Problem / Opportunity

V0.1 + V0.2 + V0.3 已经把"选元素 → 评论 → 样式预览 → 结构化导出"的闭环跑通了，但视觉走查中最常见的一类问题还没法精确表达：

1. 用户说"这个按钮和标题之间太挤"，但不知道具体差几像素。
2. 用户说"卡片宽度不对"，但没法直接读出当前宽度。
3. 用户说"这个元素离右边距太远"，但没法量化"远"是多少。
4. AI / 开发拿到记录后，仍然需要打开 DevTools 自己测量。

V0.4 的机会是把"测距"从 DevTools 抽出来，作为可视化标注层直接在 Panel 和 Overlay 里完成，并把测距结果结构化写入记录。

## 2. Goal and Success Metrics

目标：在 V0.3 的元素选择和评论体系上，增加元素尺寸读取、元素与视口/父容器/兄弟元素的测距、测距结果保存到记录，JSON 和 Prompt 输出包含测距信息。

成功标准：

1. 用户选中元素后，能在 Panel 中直接看到宽高（V0.1 已有 `rect`，V0.4 强化展示并加单位）。
2. 用户能看到选中元素与视口四边的距离（上下左右）。
3. 用户能看到选中元素与父容器四边的距离。
4. 用户能进入"双元素测距"模式，先选第一个元素再选第二个，Overlay 显示水平/垂直距离线。
5. 用户能把当前测距结果作为 `measurements` 字段附加到记录里。
6. 导出 JSON 包含 `measurements` 字段。
7. AI Prompt 中每条记录附"测距：…"子段落。
8. 页面滚动 / resize 后测距线位置和数值正确更新。
9. V0.3 评论、样式、Prompt 分组等闭环不被破坏。

## 3. Target Users and Main Scenarios

| 用户 | 场景 | V0.4 要解决的问题 |
|---|---|---|
| AI 编程用户 | 让 AI 调整间距 | Prompt 中包含"该按钮 marginTop 当前 24px，期望 12px"等量化信息 |
| 产品经理 | 验收"间距过大 / 过小" | 一眼看到具体像素，不再凭感觉描述 |
| UI/UX 设计师 | 检查设计稿还原度 | 量化元素到视口、父容器、邻近元素的距离 |
| 前端开发者 | 拿到改稿单后定位问题 | 知道"差多少 px"，不必反复打开 DevTools |

## 4. Scope

### 4.1 元素尺寸增强展示

输入：当前选中元素。

处理：

1. Panel 的元素信息区块新增"尺寸"分组：`width × height`（含 px 单位）。
2. 数值精度：取整（不显示小数）。
3. 在 Overlay 上为 selected 元素叠加尺寸标签（位于元素右上角或下方，自动避让视口边缘）。

输出：用户选中元素后立即看到精确尺寸。

### 4.2 视口距离

输入：当前选中元素的 `getBoundingClientRect`。

处理：

1. 计算 `top`、`right`、`bottom`、`left` 到视口四边的距离。
2. Panel 新增"距视口"分组：4 个数值（上下左右）。
3. 不在 Overlay 上画视口边线（避免视觉太重）。

输出：用户能看到"该元素离屏幕顶部 120px、离右边 240px"等数据。

### 4.3 父容器距离

输入：当前选中元素和其父元素。

处理：

1. 找到最近的有实际边界的 HTMLElement 父元素（跳过 body 直接父元素以外的特殊情况：父元素 rect width/height = 0 时退回 `document.documentElement`）。
2. 计算选中元素到父容器四边的距离。
3. Panel 新增"距父容器"分组：4 个数值 + 父容器 selector（截断展示，超过 32 字符显示省略号）。
4. 在 Overlay 上用虚线短线段标记父容器四边对齐位置（仅在 hover 父容器距离行时显示，避免常驻干扰）。

输出：用户能看到元素在父容器中的相对位置。

### 4.4 双元素测距

输入：用户在 Panel 点击"开始测距"按钮，然后依次选中两个元素。

处理：

1. 进入测距模式后，鼠标 hover 任意元素仍走 V0.3 高亮逻辑。
2. 第一次点击选中元素 A，第二次点击选中元素 B。
3. Overlay 同时显示 A 和 B 的高亮框，并在两元素之间绘制：
   - **水平距离**：从 A 的右边到 B 的左边（或反向，取绝对值）。
   - **垂直距离**：从 A 的下边到 B 的上边（或反向）。
   - 距离线上叠加数值标签。
4. Panel 显示双元素摘要：`A selector × W×H`、`B selector × W×H`、水平距离、垂直距离、中心点距离（直线）。
5. 提供"重新测距"按钮（清空 A、B，重新进入第一次点击状态）。
6. 提供"退出测距模式"按钮（回到 V0.3 单元素选择模式）。
7. 测距模式中保存记录时：`scope` 仍为 `element`，`element` 字段使用 A 元素，`measurements.pair` 包含 B 元素信息和距离。

输出：用户能记录"按钮和图标之间应该是 16px"这种双元素关系。

### 4.5 测距结果保存到记录

输入：当前选中元素的测距信息（视口、父容器、可选的双元素测距）。

处理：

1. CommentEditor 旁新增"附加测距"复选框（默认勾选，记得用户上次选择）。
2. 勾选时，保存记录会写入 `measurements` 字段。
3. 不勾选时，`measurements` 为 `null`。
4. 双元素测距模式下，复选框强制为 true 且禁用，提示"双元素测距记录必须附测距信息"。
5. 编辑模式（V0.3）下，记录原有 `measurements` 可见且可重新勾选/取消。

输出：用户能精确控制每条记录是否带测距数据。

### 4.6 Measurements 数据结构

```ts
type Measurements = {
  size: { width: number; height: number };
  viewport: { top: number; right: number; bottom: number; left: number };
  parent: {
    selector: string;
    distances: { top: number; right: number; bottom: number; left: number };
  } | null;
  pair: {
    selector: string;
    text: string;
    rect: { x: number; y: number; width: number; height: number };
    horizontalDistance: number;
    verticalDistance: number;
    centerDistance: number;
  } | null;
};
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `size` | `{width,height}` | 选中元素自身尺寸 |
| `viewport` | 4 个数值 | 元素到视口四边的距离 |
| `parent` | object \| null | 父容器测距，null 表示无可读父容器 |
| `pair` | object \| null | 双元素测距，null 表示未进行双元素测距 |

距离单位统一为 px，取整。`horizontalDistance` 和 `verticalDistance` 为元素边到边的距离（取绝对值，不带方向）。`centerDistance` 为两元素中心点欧几里得距离。

### 4.7 EditRecord 扩展

```ts
type EditRecord = {
  // ... V0.3 fields
  measurements: Measurements | null;
};
```

`measurements` 为 `null` 表示该记录未附加测距。V0.3 / V0.2 / V0.1 导入时默认补 `null`。

### 4.8 AI Prompt 升级

输入：每条带 `measurements` 的记录。

处理：

1. Prompt 中每条记录附"测距：" 子段落（仅在 `measurements !== null` 时输出）。
2. 子段落内容：
   ```
   测距：
   - 当前尺寸：W×H
   - 距视口：上 T / 右 R / 下 B / 左 L
   - 距父容器（{selector}）：上 T / 右 R / 下 B / 左 L
   - 与目标元素（{B.selector}）：水平 H、垂直 V、中心 C
   ```
3. 父容器和双元素测距如果不存在则该子项不输出，避免空字段。
4. 总览段落保持 V0.3 不变。

输出：AI 能根据具体像素值精准修改。

### 4.9 JSON Import / Export

输入：包含 V0.1–V0.4 记录的 JSON。

处理：

1. V0.4 导出使用 `version: "0.4"`。
2. 导入兼容 `0.1` / `0.2` / `0.3` / `0.4`：
   - V0.1–V0.3 记录 `measurements` 默认补 `null`。
   - V0.4 记录完整保留 `measurements`。
3. 不识别字段被忽略。

输出：JSON 可跨版本流通。

### 4.10 退出编辑模式清理

输入：用户退出编辑模式。

处理：

1. 清空当前选中元素的测距 Overlay 标签。
2. 清空双元素测距状态。
3. 重置 `attachMeasurements` 默认勾选（不持久化）。

输出：退出后页面无插件残留。

## 5. Non-goals

V0.4 不做：

1. 设计稿对比（不接入 Figma / Sketch）。
2. 自动布局修复或重排。
3. 复杂网格分析（多个元素同时测距）。
4. 自定义参考线（手动拖拽辅助线）。
5. 像素级精度调整（不显示亚像素）。
6. 测距数据的反向应用（不允许用户输入"目标 16px"自动调整页面）。
7. 跨 iframe 测距。
8. 测距快照截图。
9. 多个测距对（每条记录最多一个 pair）。

## 6. Requirements

### R1：元素尺寸展示

Given 用户已选中元素
When Panel 更新
Then Panel 展示"尺寸：W × H"，且 Overlay 显示尺寸标签

通过标准：

1. 尺寸数值取整。
2. 标签位置自动避让视口边缘。
3. selected 元素切换时数值实时更新。

### R2：视口距离

Given 用户已选中元素
When Panel 更新
Then Panel 展示"距视口：上 T / 右 R / 下 B / 左 L"

通过标准：

1. 4 个数值取整。
2. 元素跨出视口时显示负值（例如左边在视口外 -20）。

### R3：父容器距离

Given 用户已选中元素，且元素有非零父容器
When Panel 更新
Then Panel 展示"距父容器：上 T / 右 R / 下 B / 左 L"

通过标准：

1. 父容器 selector 截断到 32 字符。
2. 无可读父容器（例如直接子元素是 `<html>`）时显示"无父容器"。

### R4：双元素测距

Given 用户在 Panel 点击"开始测距"按钮
When 用户依次点击元素 A 和元素 B
Then Overlay 显示 A、B 高亮框和水平/垂直距离线

通过标准：

1. 距离数值显示在距离线上。
2. 提供"重新测距"和"退出测距模式"按钮。
3. 重新测距清空 A、B。
4. 双元素测距时禁用 V0.3 单选切换。

### R5：保存测距到记录

Given 用户当前有测距数据
When 用户勾选"附加测距"并保存记录
Then 记录 `measurements` 包含完整数据

通过标准：

1. `attachMeasurements = false` 时 `measurements` 为 `null`。
2. 双元素测距强制 `attachMeasurements = true`。
3. 编辑现有记录时显示原有 `measurements`，允许重新勾选。

### R6：Prompt 输出

Given 当前 session 含有带 `measurements` 的记录
When 用户复制 Prompt
Then Prompt 中每条记录后附"测距：…"子段落

通过标准：

1. `measurements = null` 的记录不输出测距子段落。
2. `parent` 或 `pair` 为 null 时对应子项不输出。

### R7：JSON 兼容

Given 用户导入 V0.1–V0.3 JSON
When 解析完成
Then 所有记录 `measurements` 默认为 `null`，其他字段保持 V0.3 兼容规则

### R8：滚动 / resize 更新

Given Overlay 显示尺寸标签或测距线
When 用户滚动页面或 resize 视口
Then 标签和距离线位置实时更新，数值不变

通过标准：

1. 数值是元素本身的尺寸或距离，不随视口变化。
2. 标签 / 距离线相对元素的位置正确。

### R9：测距模式清理

Given 用户处于双元素测距模式
When 用户退出编辑模式
Then 测距状态清空，Overlay 无残留

## 7. User Stories

1. 作为产品经理，我希望看到"这个按钮高度 48px"，而不是"这个按钮看起来太高"，让开发知道改到多少。
2. 作为 UI 设计师，我希望测量按钮和标题的间距，然后写"应该改为 16px"。
3. 作为 AI 编程用户，我希望 Prompt 里有"当前 marginTop=24px，期望 12px"，AI 能直接生成 CSS。
4. 作为前端开发者，我希望拿到改稿单后不用反复打开 DevTools 测量。

## 8. Acceptance Criteria

1. `cd extension && npm run verify` 通过。
2. Panel 显示尺寸、距视口、距父容器三组数值，数值随选中元素变化实时更新。
3. 测距模式下能依次点击两个元素，Overlay 显示距离线和数值。
4. 重新测距 / 退出测距模式按钮工作正常。
5. CommentEditor 旁的"附加测距"复选框可勾选/取消。
6. 保存的记录 `measurements` 与界面显示一致。
7. 编辑记录时能看到并修改 `measurements` 附加状态。
8. JSON 导出含 `version: "0.4"` 和 `measurements` 字段。
9. 导入 V0.1 / V0.2 / V0.3 JSON 全部补齐 `measurements: null`。
10. Prompt 中带 `measurements` 的记录附"测距：…"子段落。
11. 滚动和 resize 后 Overlay 标签 / 距离线正确更新。
12. 退出编辑模式后页面无插件残留 DOM。
13. V0.3 评论、样式、Prompt 分组等闭环不被破坏。

## 9. Dependencies

1. 延续 V0.3 的 Content Script、Panel、Overlay、样式编辑器、记录元数据架构。
2. 不新增后端服务。
3. 不新增大型 UI 组件库（继续手写控件 + Shadow DOM）。
4. 测距线和标签在 Overlay Shadow DOM 内自绘，避免污染宿主页面。

## 10. Risks and Edge Cases

| 风险 | 影响 | 降级方案 |
|---|---|---|
| 元素 rect 为 0（display: none） | 无法测距 | Panel 显示"该元素当前不可见" |
| 父容器为 `<html>` 或无法读取 | 父容器距离失效 | Panel 显示"无父容器距离" |
| 双元素相互重叠 | 距离为负 | 取绝对值，并在数值前加"重叠"标识 |
| 跨 iframe 测距 | 坐标系不同 | V0.4 不支持，提示用户 |
| 元素跨出视口 | 视口距离为负 | 显示负值，不阻断流程 |
| 测距模式下用户切换 tab | 状态丢失 | 退出测距模式回到 V0.3 单选 |
| 距离线遮挡内容 | 影响阅读 | 距离线半透明，且只在 hover 行时强调 |
| 数值精度争议（小数） | UX 不统一 | V0.4 统一取整，不显示小数 |
| Overlay 标签超出视口 | 用户看不到数值 | 标签位置自动镜像（右上 → 左上 → 下方） |
| 测距数据老化 | 记录保存后页面变化导致测距失真 | 不实时同步，记录值就是保存时的快照 |

## 11. Rollout Notes

V0.4 开发顺序：

1. 数据结构与 JSON 兼容（含测试）。
2. 测距读取模块（`measurement.ts`）。
3. Overlay 渲染（尺寸标签、距离线）。
4. Panel UI（尺寸、视口、父容器分组）。
5. 双元素测距模式（runtime state + handlers）。
6. CommentEditor 附加测距复选框。
7. Prompt 测距子段落。
8. 测试页面与文档同步。

V0.4 完成后，再进入 V0.5 共享元素。

## 12. Open Questions

V0.4 当前默认决策：

1. 数值统一取整，不显示小数（已确认）。
2. 双元素测距强制附加测距数据（已确认）。
3. 测距模式下禁用单元素选择切换（已确认）。
4. 父容器只读最近的有实际边界的 HTMLElement（已确认）。
5. `measurements` 字段为快照，不随页面变化更新（已确认）。
6. 不支持跨 iframe 测距（已确认）。
7. 每条记录最多一个 `pair`（已确认）。
